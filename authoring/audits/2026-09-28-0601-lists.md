## B. Accuracy

- [x] **B1. Methods table returns.** The "List Methods/Functions" table shows `[1, 2].append(3)` → `[1, 2, 3]`, and the same pattern for `insert`, `extend`, `remove`, `clear`, `sort`, and `reverse`. These calls return `None` and modify the list in place. Show the list state after the call, for example `lst.append(3)` → `lst` is `[1, 2, 3]`.
- [x] **B2. Functions vs. methods.** The same table mixes methods with the built-in functions `sorted()`, `reversed()`, `len()`, `max()`, `min()`, and `sum()`. Split the table or label each row as a function or a method.
- [x] **B3. Wrong chapter reference.** The `any()` / `all()` note says "Chapter 12 (Iterators & Generators)". It is Chapter 11.
- [x] **B4. Wrong variable names.** "Objects and Values" ends with "whether `a` and `b` refer to the same string", but the preceding code uses `c` and `d`.
- [x] **B5. String interning caveat.** `a = 'banana'; b = 'banana'; a is b` returns `True` because of string interning, a CPython implementation detail. Add a one-line caveat so students do not generalize it.
- [x] **B6. "Elements" definition.** "The value literals in a list are called elements" is inaccurate. Elements are values, not necessarily literals.
- [x] **B7. Shallow-copy wording.** "Shallow copy has given us two variable names referencing the same object" is inaccurate. The outer lists are different objects; only the inner lists are shared.
